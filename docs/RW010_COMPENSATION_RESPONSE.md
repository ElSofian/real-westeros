# Personal response to a paid voluntary compensation

**Original CK3 scripts; static-checked, not engine-tested.** Receiving money does
not establish personal reconciliation. This slice lets the original beneficiary
respond to one exact new payment, separately from financial consent and legal facts.

## Fresh payment, separate personal choice

After both ordered native gold effects in a new valid compensation settlement, a
temporary same-call payment token identifies the exact parent case. Before either
receipt notice, an original helper rechecks complete private paid receipt identity,
requires that token to equal the selected case and rejects existing response data.
It copies paid amount, revision and original payment date, records pending state
and one **thirty-day** response window, then stamps schema 1. The token is cleared
before notices. No old receipt, archive read, delayed reply or source migration
creates or renews a window. Ordered code is not atomic transfer or crash recovery.

Only the captured original client can decide while alive, with the original payer
still living, exact retained private case/paid receipt and matching amount/revision/
date, pending response and live window. The payer, mediator, later ruler, house head
and heir cannot decide for them. This is a personal statement after a completed
script payment, so it requires neither new funds nor current land/rank/jurisdiction,
peace or freedom to transfer money again. It cannot authorize another payment.

The beneficiary may:

- **Appreciate:** consume the response window, record choice/date, then add **+5
  personal opinion for two years** toward the original payer only if that pair's
  same modifier is absent. Another case cannot stack it or refresh its expiry.
- **Acknowledge without rapprochement:** consume the response and record choice/date,
  without an opinion benefit, penalty, refund or financial effect.
- **Leave it undecided:** no recorded response or automatic benefit. Reviewing within
  the original window preserves the choice; reading never extends it.

There is no purchased pardon, erased resentment, accepted apology, native legal
immunity or completed original service. A beneficiary may appreciate this act while
retaining an earlier negative opinion modifier. Other original apology choices keep
their own unchanged identities, windows and effects. A modest financial appreciation
is not a universal reputation score or a house/dynastic consequence.

## Private history and bounded notices

Existing private compensation panels display pending, appreciated, neutral, missing
or unavailable/unanswered response information. A historical positive choice does
not guarantee a currently active opinion bonus and never renews it. Silence or
missing old metadata means no recorded personal statement, not consent or refusal.
If the original beneficiary dies before responding, the old window provides no
choice to an heir and its unavailable status is displayed without blame.

Only the original provider/client can read these financial responses through the
existing complete case/receipt guard. On a decision, only the original living payer
receives one notice, after response consumption and any conditional opinion effect.
The mediator/house/crown learns nothing from this flow. The unchanged parent case
owns persistence: original 1825-day retention, provider-death ending and sixty-day
cleanup. No new story, index, world scan, hook, reminder or periodic callback is
introduced. Response dates/windows never renew the original affair's memory.

AI and player have identical guards/effects, with both explicit choices and silence.
The already scheduled payment receipt supplies the opportunity; traits and existing
opinion weight the optional reaction. Actual AI behavior, balance, timing and native
modifier expiration remain unverified. No no-tyranny helper, bank/title/war action,
third-party message, paid service, runtime LLM or Python is used.
