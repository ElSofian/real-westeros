# Personal response to explicit deferred-support renunciation

**Original CK3 scripts; static-checked, not engine-tested.** This extends the
existing private deferred favor/gold support record, not native justice or a
universal reputation system. Provider renunciation remains a free explicit choice.

Only a new explicit provider renunciation opens a thirty-day response window for
the original client. The accepted promise is consumed and its terminal date written
first; a same-call provider token then binds the response to exact serial, accepted
revision, consideration and finished date before existing party notices. The token
is cleared immediately. A repeated call for that serial cannot reopen the window.
Older renunciations, neutral expiry, client withdrawal, performance, offer closure
and private review never manufacture a response opportunity.

The original living client may choose:

- **Resent the renunciation:** −15 personal opinion of the original living provider
  for two years, only if this exact opinion modifier is absent for the pair. A
  later promise cannot stack or refresh an active modifier.
- **Take note:** record a neutral response without adding or removing opinions,
  forgiving another affair, or rewriting the provider's renunciation.

Either choice consumes the pending window and records response/date before any
opinion effect or one private provider notice. Replaying the panel cannot change
the response. Waiting or reviewing never renews the window; silence expires without
resentment, consent, pardon or legal judgment. The shared annual service cooldown
and original promise deadlines are unchanged. No funds, prestige, native favor,
secret, crime, title or imprisonment state is touched. Existing grievances remain.

Full existing private-ticket identity and explicit deferred mode precede response
access. The client alone may respond; an observer, mediator, heir, copied successor
record or stale panel for an older promise cannot act. Exact serial/revision/term
and terminal-date comparisons keep retained response metadata inert if a newer
offer replaces the latest provider record. This is latest personal history, not a
new durable ledger or inherited duty. Both parties can review the latest private
status; provider death/reference loss disables a personal response.

AI and players use the same guards and costs. Existing renunciation notices offer
both choices, with vengeful/forgiving trait weights for AI. No new periodic scan,
callback, reminder chain, interaction target pool or world policy is added.

Twelve adversarial source tests check identity/mode, actor, fixed deadline, no
legacy backfill, token ordering, terminal consumption, no stacking/refresh, neutral
acknowledgment, private notices, native-state isolation and EN/FR localization.
These tests do not simulate CK3. FREN-01…08 in FINAL_ENGINE_TESTS.md remain unrun;
window expiry, saved scopes, opinion duration, save/load, actual AI choices/privacy
and compatibility require the owner's final campaign. No new source collection,
paid service, runtime Python/LLM or intermediate engine run is required.
